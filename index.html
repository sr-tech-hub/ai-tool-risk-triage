Method

How we score

Seven questions every vendor gets asked, checked in the same order every time.

Data level
The most sensitive data ticked sets the level: Public, then Internal, then Confidential (source code, financial), then Restricted (customer PII, HR/health). Higher levels check more rules.
Rule
One check against one vendor answer, for example "R1: the vendor does not train its models on our data". Each rule starts at a data level.
Met
The vendor's answer passes as it is.
Met with setup
It passes once a setting or contract step is done, such as switching on SSO. That step becomes a condition.
Not met
A Required rule that is not met blocks that plan. A Recommended rule that is not met adds a workaround as a condition instead.
Unknown
Counts as not met. If we can't confirm it, we don't assume it.
Order tried
The Standard plan with all the data asked for, then the Enterprise plan. If both are blocked, the same again without the most sensitive data, as long as some of the requested data is left. The first plan with nothing blocking it wins.
Approve
The Standard plan passes for all the data asked for, with no conditions.
Approve with conditions
A plan passes, but only on the Enterprise plan, without some data, or after setup steps. Every condition is listed.
Deny
No plan passes, even with the most sensitive data taken out. The blocking rules are listed so the requester knows what would have to change.
